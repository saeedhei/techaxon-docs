# Code Comment Rule

Keep comments concise and meaningful.

When a comment is needed, prefer **one comment for a block or piece of logic** rather than adding comments to every line.

Avoid adding or changing comments on multiple lines unnecessarily. In GitHub reviews, each changed comment line appears as a separate change, which can make the diff larger and harder to review.

Use comments to explain **why** something is done when the code itself is not clear, rather than explaining every line of code.
